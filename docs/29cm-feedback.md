# /29cm 실행 피드백 (task-observer)

대상: `.claude/commands/29cm.md`
세션: 클라우드 원격 세션에서 `/29cm`을 2회 호출. 두 번 모두 수집에 실패했다.
이 세션은 임시 컨테이너라 task-observer의 관찰 로그를 영구 보관할 곳이 없다. 그래서 관찰 내용을 이 문서와 커밋으로 남긴다.

## 실행 결과

| 시도 | 결과 |
|---|---|
| 1회차 | 파트너센터 직접 접속 403, 로그인된 브라우저 도구 없음. #매출-보고에는 게시하지 않고 이상표님 DM으로 실패 사유를 전송했다. |
| 2회차 | 환경이 동일해 같은 실패. 재시도 금지 규칙과 중복 DM 방지를 위해 DM을 다시 보내지 않았다. |

이 루틴은 로컬 환경에서 한 번 돌려 봐야 검증된다. 아래 항목 중 1~3번은 실제 실행에서 겪은 문제이고, 4~6번은 명령 파일을 읽으며 찾은 위험이다. 4~6번은 실행으로 확인하지 못했다.

## 관찰

### 1. 실행 환경 전제가 명령 안에 없다
- **Issue:** 명령은 로그인된 Chrome 제어를 전제하지만 이 사실이 어디에도 적혀 있지 않다. 클라우드에서 호출하면 실패 처리까지 불필요한 시도를 한다.
- **개선:** "실행 환경" 절을 추가하고, 로컬 전용임을 명시했다. 클라우드 호출은 바로 실패 처리로 보낸다. (반영함)
- **원칙:** 환경 의존이 큰 루틴은 첫머리에 전제를 적고, 전제가 깨지면 수집 전에 중단한다.

### 2. 사전 점검(preflight) 단계가 없다
- **Issue:** 도구·로그인 확인이 실패 처리 문단에만 있어 1단계 중간에 실패하면 어디서 멈출지 모호하다. 반쯤 수집한 뒤 중단할 수도 있다.
- **개선:** "0단계 사전 점검"을 추가했다. 브라우저 도구, Slack 도구, 통계 페이지 접속과 로그인 여부를 수집 전에 확인한다. (반영함)
- **원칙:** 비싸고 되돌릴 수 없는 단계 앞에는 싼 점검을 둔다.

### 3. 실패 사유와 중복 알림 규칙이 부족하다
- **Issue:** 실패 사유 예시가 "로그인 필요" 하나뿐이다. 403 차단, 도구 없음, 검산 불일치는 언급이 없다. 같은 날 같은 사유로 재호출되면 DM을 또 보낼지 정해져 있지 않다.
- **개선:** 실패 4종을 열거하고, 같은 날 같은 사유의 중복 DM은 보내지 않도록 했다. Slack 도구가 없을 때의 대체 경로도 적었다. (반영함)
- **원칙:** 실패 경로도 성공 경로만큼 입력·출력을 정해 둔다.

### 4. 검산 불일치 때 행동이 정해져 있지 않다 (실행으로 확인하지 못함)
- **Issue:** 3단계는 "원 단위까지 맞춘 뒤에만 작성"이라고만 하고, 맞지 않을 때 어떻게 할지는 없다. 무인 실행에서는 근사값으로 게시할 위험이 있다.
- **개선:** 재수집 3회 후에도 불일치하거나 차액이 설명되지 않으면 게시하지 않고 DM으로 차액과 함께 보고하도록 했다. (반영함)
- **원칙:** 검증 게이트는 "통과 조건"과 함께 "실패 시 행동"을 정의한다.

### 5. UI 좌표와 상품명 목록이 깨지기 쉽다 (실행으로 확인하지 못함)
- **Issue:** 클릭 좌표는 1568x744 창에 묶여 있다. JS의 상품 라인 목록은 신제품이 나오면 낡는다.
- **개선:** 좌표가 빗나가면 버튼 텍스트로 찾도록 대안을 적었다. 목록에 없는 신규 라인은 옵션명을 뗀 이름으로 합산하고 갱신 필요를 알리도록 했다. (반영함)
- **미해결:** 목록 자체를 명령 파일 밖으로 빼 관리하는 방법은 정하지 않았다. 목록 갱신 담당과 주기는 이상표님이 정해야 한다.

### 6. 날짜 계산이 PowerShell 전용이다
- **Issue:** 전일 계산 명령이 PowerShell로만 적혀 있어 bash 환경에서는 쓸 수 없다.
- **개선:** bash 명령(`TZ=Asia/Seoul date -d yesterday '+%F (%a)'`)을 병기했다. macOS의 `date`는 `-d` 옵션이 다르므로 별도 확인이 필요하다. (반영함)

## 함께 받은 이식 가이드에서 확인되지 않은 부분

- `claude mcp add ... http://127.0.0.1:41100/mcp` (Chrome)와 `https://slack.com/api/mcp` (Slack) 주소는 이 세션에서 맞는지 확인하지 못했다. 그대로 쓰지 말고 Claude in Chrome 확장과 Slack 커넥터가 안내하는 값을 쓸 것.
- `claude -p "진행" --dangerously-skip-permissions`는 모든 권한 확인을 끈다. 스케줄러에 걸기 전에 `settings.json`의 `permissions`로 필요한 도구만 허용하는 방식을 먼저 검토할 것.
- 로컬에서 `/29cm`이 슬래시 명령으로 동작하려면 이 파일이 있는 저장소 또는 `~/.claude/commands/`에 둬야 한다. 이 저장소의 `.claude/commands/29cm.md`가 이미 그 위치다.

## 다음 단계

1. 로컬(로그인된 Chrome이 있는 PC)에서 `/29cm`을 실제로 한 번 실행해 0~5단계가 문제없이 도는지 확인한다.
2. 그때 실제로 발생한 문제(좌표 어긋남, 가상 스크롤, 검산 불일치 등)를 이 문서에 이어서 기록한다.
