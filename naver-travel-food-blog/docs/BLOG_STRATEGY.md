# BLOG_STRATEGY — 여행 / 맛집 블로그 운영 전략

- 문서 상태: 설계 초안 (승인 대기)
- 근거 기호(R1~R5, N1~N8, A1, F1~F2)는 `PROJECT_OVERVIEW.md` 6절 참고

## 1. 전략의 출발점: 네이버가 공식적으로 밝힌 방향

여행·맛집은 네이버가 "경험과 후기"를 가장 직접적으로 찾는 분야다. 공식 자료에서 확인되는 방향은 다음과 같다.

| 공식 자료가 말하는 것 | 이 블로그에 주는 의미 |
|---|---|
| 블로그 신뢰도는 주제 집중도(Context), 정보 품질(Content), 소비·생산의 연쇄 반응(Chain)으로 평가한다 (N1) | 여행·맛집이라는 주제를 벗어나지 않고 꾸준히 쌓는다 |
| 문서 평가는 주제 적합도, 경험 정보, 정보의 충실성, 독창성, 적시성 등을 본다. 비체험 후기는 순위에서 밀린다 (N2) | 직접 다녀온 글이 중심이어야 한다 |
| 자동 생성된 저품질 콘텐츠, 실제 경험에 기반하지 않은 광고성 도배글을 더 정교하게 판별한다 (N3) | AI로 양을 늘리는 방식은 선택지가 아니다 |
| 좋은 콘텐츠 5원칙: 직접 경험한 지식, 일관된 주제, 거짓 없는 진정성, 읽기 쉬운 구조, 최신성 유지 (N5) | 이 5가지가 글 검수 기준의 뼈대다 |
| AI 도구를 썼다고 무조건 불이익은 없다. 다만 최종 검토와 편집을 거쳐 실제 경험과 지식을 녹여야 한다 (N5) | AI는 보조 도구로 쓰고 사람이 완성한다 |
| '후쿠오카 여행' 같은 검색에서 경험 글을 관심사별 소제목으로 묶어 보여주는 '경험 UGC 블록'을 제공한다 (N8) | "지역 + 구체적 관심사"(근교 당일치기, 아이와 함께 등) 단위로 글을 쓴다 |
| 해외여행 검색에서 AI가 블로그 리뷰 등을 바탕으로 맛집, 카페, 가볼 만한 곳, 액티비티를 주제별로 정리한다 (N7) | 해외 글도 "도시 + 즐길거리 유형"으로 구성한다 |

## 2. 블로그의 정체성

**한 문장 정의:** 직접 다녀온 지역을 기준으로, 그 지역의 여행 동선과 맛집을 함께 보여주는 블로그.

- 여행 블로그와 맛집 블로그를 따로 운영하는 방식이 아니라, **지역**이라는 하나의 축으로 묶는다.
- 독자가 얻는 것: "이 지역에 가면 어디를 어떤 순서로 가고, 어디서 무엇을 먹으면 되는지"를 직접 다녀온 사람의 기록으로 확인한다.
- 구체적인 독자층(연령, 동행 유형, 예산대)은 아직 정하지 않았다. 6절 참고.

## 3. 콘텐츠 방향: 4가지 유형

| 유형 | 내용 | 방문 필요 여부 | 역할 |
|---|---|---|---|
| A. 여행 후기 | 직접 다녀온 여행지, 코스, 숙소의 후기 | 필수 | 경험 정보의 핵심 |
| B. 맛집 후기 | 직접 방문한 식당·카페 후기 | 필수 | 경험 정보의 핵심, 발행 빈도 확보 |
| C. 정보성 글 | 준비물, 교통, 코스 짜는 법, 시기별 정보, 비교 정리 | 방문 경험 권장, 없으면 그 사실을 밝힘 | 검색 유입, 후기 글로 연결 |
| D. 지역 모음글 | 한 지역에 대해 쓴 A·B·C를 묶어 안내하는 글 | 해당 지역 방문 글이 쌓인 뒤 작성 | 지역 단위 연결 |

### 지역 기반 연결 방식

한 번의 방문에서 여러 글이 나오고, 글끼리 연결한다.

```
[지역 모음글 D]  예) ○○ 1박 2일 총정리
   ├─ [여행 후기 A]  코스, 명소, 숙소
   ├─ [맛집 후기 B]  점심, 저녁, 카페 (각각 한 편)
   └─ [정보성 글 C]  교통, 예약, 준비물
```

- 맛집 후기 끝에는 같은 지역의 여행 후기를, 여행 후기 끝에는 같은 지역의 맛집 후기를 안내한다. R1의 Outline Builder 프롬프트가 "마지막에 독자가 이어서 읽을 내 글 2개"를 넣도록 한 것과 같은 원리다.
- R4는 대표 글 등록 기능을 "방문자가 내 다른 글까지 둘러보게 만드는 기능"으로 소개한다. 지역 모음글이 대표 글 후보다(기능 위치와 효과는 실제 화면에서 확인 필요).

## 4. 운영 방식

### 4.1 한 번의 방문으로 여러 글 만들기

방문은 비용이 드는 자원이다. 방문 한 번을 여러 글로 나누려면 **방문할 때 기록을 충분히 남기는 것**이 가장 중요하다. 기록 항목은 `CONTENT_GUIDELINES.md`의 방문 기록 카드에 정리했다.

### 4.2 꾸준함

- R3의 운영자는 "잘 쓰는 것보다 계속 쓰는 게 먼저", "루틴이 된 사람만 숫자가 움직인다"고 강조한다. 개인의 경험담이지만 N1의 주제 집중도, N5의 일관된 주제·최신성 유지와 방향이 같다.
- N2는 "매일 작성하면 불이익을 받느냐"는 질문에 문서 단위로 품질을 보므로 작성 주기와 무관하다고 답한다. 따라서 발행 빈도 자체를 목표로 삼지 않고, **유지할 수 있는 주기**를 정한다.
- 발행 주기는 사용자가 블로그에 쓸 수 있는 시간에 달려 있어 아직 정하지 않았다(R1의 Niche Strategist 프롬프트도 하루 가용 시간을 먼저 묻는다).

### 4.3 최신성 관리

- N5는 정보가 바뀌면 글을 수정하라고 권한다. 여행·맛집은 가격, 영업시간, 폐업 여부가 자주 바뀐다.
- 모든 후기에 방문일을 적고, 가격·영업시간에는 확인일을 적는다. 주기적으로 오래된 글을 점검하는 절차를 자동화 대상에 넣는다(`AUTOMATION_ARCHITECTURE.md`).

### 4.4 AI의 역할

- AI는 글감 정리, 목차 제안, 메모를 문장으로 다듬기, 점검에 쓴다.
- 경험, 판단, 평가(맛있었는지, 다시 갈지)는 사용자의 메모에서만 나온다. AI가 채워 넣지 않는다.
- 초안은 반드시 사용자가 읽고 고친 뒤 발행한다.

## 5. 하지 않는 것

- 방문하지 않은 곳의 후기 형식 글
- 다른 블로그 글을 재구성한 글, 출처 없는 짜깁기 (N5의 "무분별한 복제와 생성")
- 노출만을 위한 키워드 반복, 본문과 무관한 태그·이미지 (N5, A1)
- 검수 없는 자동 발행, 예약 대량 발행
- 경제적 대가를 받고도 표시하지 않는 글 (F1, N5)

## 6. 아직 결정되지 않은 사항

| 항목 | 왜 필요한가 |
|---|---|
| 주 독자층 (동행 유형, 연령대, 예산대) | 글의 관점과 키워드 선택 기준이 된다. N6의 셀프 체크 1번이 "누가, 언제, 어떤 상황에서 찾는 정보인가"다 |
| 국내와 해외의 비중 | 카테고리 구조와 발행 계획이 달라진다 |
| 시작 지역 (이미 다녀온 곳, 자주 가는 곳) | 첫 글들은 기존 방문 기록에서 나와야 한다 |
| 발행 주기와 주당 가용 시간 | 로드맵의 속도를 정한다 |
| 과거 방문의 사진·기록 보유 여부 | 기록이 충분한 방문만 후기로 쓸 수 있다 |
| 블로그 신규 개설 여부, 기존 블로그 사용 여부 | 세팅 단계와 주제 일관성 판단이 달라진다 |
| 얼굴·동행인 노출, 필명 등 개인정보 원칙 | 사진 선별 기준에 필요하다 |
