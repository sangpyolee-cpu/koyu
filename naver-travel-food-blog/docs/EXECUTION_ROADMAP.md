# EXECUTION_ROADMAP — 단계별 구축 및 운영 계획

- 문서 상태: 설계 초안 (승인 대기)
- 근거 기호는 `PROJECT_OVERVIEW.md` 6절 참고
- 각 단계에는 기간 대신 **완료 조건**을 둔다. 사용자가 쓸 수 있는 시간과 방문 빈도가 정해지지 않았기 때문이다.

## 전체 순서

```
0단계 설계 승인 ─▶ 1단계 블로그 세팅 ─▶ 2단계 수동 운영 ─▶ 3단계 반자동화
                                                               │
                              5단계 수익화 ◀─ 4단계 회고 체계 ◀┘
```

각 단계는 앞 단계의 완료 조건을 충족하고 사용자가 승인한 뒤에 시작한다.

## 0단계. 설계 승인과 결정 (현재)

| 할 일 | 담당 |
|---|---|
| 8개 설계 문서 검토 | 사용자 |
| 미결정 사항 답변 (아래 "결정이 필요한 사항") | 사용자 |
| 답변을 반영해 문서 수정 | Claude Code |

**완료 조건:** 사용자가 설계를 승인하고, 최소한 블로그 주제, 시작 지역, 주당 가용 시간이 정해진다.

## 1단계. 블로그 세팅

글을 쓰기 전에 한 번 하는 설정이다. R4의 5가지 세팅을 출발점으로 하되, R4의 화면은 설명용 그림이므로 실제 네이버 관리 화면을 보며 메뉴 이름과 위치를 확인한다.

| 순서 | 할 일 | 근거 |
|---|---|---|
| 1 | 블로그 개설 또는 기존 블로그 사용 결정, 블로그명·소개 작성 | `BLOG_STRATEGY.md` |
| 2 | 검색 허용·공개 관련 기본 설정 확인 | R4 |
| 3 | 블로그 주제 1개 지정 | R4, `CATEGORY_STRUCTURE.md` |
| 4 | 카테고리 생성 (글이 생길 곳만) | `CATEGORY_STRUCTURE.md` |
| 5 | 외부 공유·CCL 설정 검토 | R4 (효과는 검증되지 않은 주장이므로 설정의 의미를 확인하고 결정) |
| 6 | 통계·어드바이저 화면 위치 확인 | R3 |
| 7 | 편집기에서 'AI 활용' 표시 기능과 장소 첨부 기능 확인 | `SEO_STRATEGY.md` 8절 |
| 8 | 확장프로그램 설치 여부 결정 (선택) | R2, R5 |

Claude Code의 역할: 각 설정이 무엇을 뜻하는지 설명하고, 확인 결과를 설정 기록 문서로 남긴다. 네이버 화면 조작은 사용자가 직접 한다.

**완료 조건:** 설정 기록이 작성되고, 빈 글쓰기 화면까지 정상 진입한다.

## 2단계. 수동 운영 (자동화 수준 0)

양식과 검수표만 가지고, 단계별 프롬프트를 직접 입력해 글을 쓴다. 이 단계의 목적은 **자동화할 가치가 있는 반복 작업이 무엇인지 실제로 확인하는 것**이다.

| 순서 | 할 일 |
|---|---|
| 1 | 방문 기록 카드, 유형별 구성, 검수표 양식을 만든다 |
| 2 | 이미 다녀온 곳 중 기록이 충분한 방문을 방문 기록 카드로 정리한다 |
| 3 | 한 지역을 골라 맛집 후기, 여행 후기, 정보성 글을 차례로 쓴다 |
| 4 | 매 글마다 G1~G4 승인 지점을 거치고 검수표를 통과시킨다 |
| 5 | 사용자가 네이버 편집기에 직접 발행한다 |
| 6 | 같은 지역 글이 모이면 지역 모음글을 쓰고 글끼리 연결한다 |
| 7 | 글마다 걸린 시간과 번거로웠던 점을 기록한다 |

첫 글은 맛집 후기를 권한다. 구성이 단순하고 방문 기록 카드 하나로 완결되기 때문이다.

**완료 조건:** 한 지역에서 네 가지 유형(A~D)을 모두 한 번 이상 발행하고, 반복되는 작업 목록이 정리된다.

## 3단계. 반자동화 (자동화 수준 1~2)

2단계에서 반복이 확인된 작업부터 스킬·명령으로 만든다. 구현 전에 각 도구의 구조를 설명하고 승인을 받는다.

| 순서 | 만들 것 | 조건 |
|---|---|---|
| 1 | 프로젝트 규칙 파일 (절대 원칙) | 3단계 시작 시 |
| 2 | 방문 기록 정리 도구 | 가장 먼저. 모든 글의 근거이기 때문 |
| 3 | 기획 도구 (제목·목차) | |
| 4 | 초안 도구 | 방문 기록 카드 연결과 "확인 필요" 표시 포함 |
| 5 | 점검 도구와 점검 스크립트 | |
| 6 | 글감 발굴 도구 | 방문 기록이 여러 건 쌓인 뒤 |
| 7 | 지역별 글 목록과 연결 글 추천 | 글이 쌓인 뒤 |

한 번에 하나씩 만들고, 실제 글 한 편에 써 본 뒤 다음 것을 만든다.

**완료 조건:** 글 한 편을 방문 기록에서 검수 통과까지 도구로 진행할 수 있고, 모든 승인 지점이 유지된다.

## 4단계. 회고 체계 (자동화 수준 3)

| 순서 | 할 일 |
|---|---|
| 1 | 주 1회 통계를 붙여 넣고 회고하는 절차를 정착시킨다 (R1의 Growth Analyst) |
| 2 | 유입 키워드에서 새 글감을 찾는 흐름을 연결한다 (R3) |
| 3 | 방문일·확인일이 오래된 글의 점검 목록을 정기적으로 만든다 (N5의 최신성 유지) |
| 4 | 회고 결과로 작성 기준과 양식을 고친다 |

**완료 조건:** 회고가 정해진 주기로 이어지고, 회고에서 나온 글감이 실제 발행으로 이어진다.

## 5단계. 수익화

`MONETIZATION_STRATEGY.md`의 순서를 따른다.

| 순서 | 할 일 | 시작 조건 |
|---|---|---|
| 1 | 애드포스트 공식 가입 조건 확인 | 4단계 진행 중 언제든 |
| 2 | 애드포스트 가입, 미디어 등록 신청 | 조건 충족 시 |
| 3 | 대가 표시 문구 확정 | 제휴·협찬을 시작하기 전 |
| 4 | 제휴 프로그램 공식 조건 조사, 적용 | 문구 확정 후 |
| 5 | 체험단·협찬 수락 기준 확정, 시작 | 문구 확정 후 |

수익화는 3·4단계와 병행할 수 있다. 다만 신청과 계약은 사용자가 직접 한다.

## 그 이후: 외부 연동 검토

통계 수집이나 발행 보조처럼 네이버 서비스에 연결되는 자동화는 네이버 약관과 정책을 확인하고 별도 승인을 받은 뒤에만 검토한다. 현재 로드맵에는 포함하지 않는다.

## 결정이 필요한 사항 (0단계에서 답변 필요)

| 번호 | 질문 | 영향을 받는 문서 |
|---|---|---|
| 1 | 블로그를 새로 만드는가, 기존 블로그를 쓰는가? 기존이라면 어떤 글이 있는가? | 전략, 카테고리 |
| 2 | 앞으로 가장 자주 쓸 글은 국내여행, 해외여행, 맛집 중 무엇인가? | 카테고리 (블로그 주제) |
| 3 | 이미 다녀왔고 사진·기록이 남아 있는 지역은 어디인가? 자주 가는 지역은? | 전략, 로드맵 2단계 |
| 4 | 블로그에 쓸 수 있는 시간은 주당 얼마인가? | 발행 주기, 로드맵 속도 |
| 5 | 주로 누구와 다니는가? (혼자, 커플, 가족, 아이 동반 등) | 독자 설정, 키워드 |
| 6 | 얼굴·동행인 노출, 필명 등 개인정보 원칙은? | 작성 기준 |
| 7 | 제3자 확장프로그램을 쓸 의향이 있는가? | SEO |
| 8 | 프로젝트 파일을 현재 저장소의 작업 브랜치에 둘지, 별도 개인 저장소로 옮길지? | 자동화 설계 |

## 위험과 대비

| 위험 | 대비 |
|---|---|
| 방문 기록이 부족해 쓸 글이 없다 | 방문할 때 기록 카드 항목을 채우는 습관을 먼저 만든다. 정보성 글로 간격을 메우되 방문 경험이 없음을 밝힌다 |
| 초안을 고치지 않고 올리게 된다 | G3(직접 수정)과 검수표 14번을 발행 조건으로 둔다 |
| 도구를 만드는 데 시간을 다 쓴다 | 2단계에서 반복이 확인된 것만, 하나씩 만든다 |
| 네이버 정책과 화면이 바뀐다 | 공식 블로그 공지를 회고 때 확인하고, 문서에 확인일을 남긴다 |
| 수익화가 콘텐츠를 흐린다 | 협찬 글 비중 상한, 대가 표시 점검 |
