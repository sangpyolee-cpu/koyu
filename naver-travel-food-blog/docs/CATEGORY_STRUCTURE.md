# CATEGORY_STRUCTURE — 카테고리 및 콘텐츠 분류 구조

- 문서 상태: 설계 초안 (승인 대기)
- 근거 기호는 `PROJECT_OVERVIEW.md` 6절 참고
- 이 문서의 카테고리 이름은 제안이다. 네이버 블로그 관리 화면의 실제 메뉴 이름과 제한(카테고리 단계 수 등)은 세팅 단계에서 화면을 보며 확인한다.

## 1. 분류의 세 층

네이버 블로그에는 성격이 다른 분류가 세 가지 있다. 혼동하지 않도록 구분한다.

| 층 | 무엇인가 | 누가 보는가 | 이 프로젝트의 기준 |
|---|---|---|---|
| 블로그 주제 | 블로그 전체에 하나 지정하는 주제 분류 | 네이버, 방문자 | 하나만 명확하게 지정한다 (R4) |
| 카테고리 | 블로그 안의 글 묶음 메뉴 | 방문자 | 지역 중심으로 단순하게 구성한다 |
| 태그 | 글마다 붙이는 키워드 | 네이버, 방문자 | 본문 키워드와 연관된 3~5개만 (R4) |

R4의 "메인 카테고리 1개만", "태그 3~5개만"은 개인 창작자의 조언이고 효과가 공식적으로 확인된 것은 아니다. 다만 N1(주제 집중도)과 N5(일관된 주제, 무관한 키워드 삽입 금지)의 방향과 맞으므로 채택한다.

## 2. 블로그 주제 (미결정)

R3의 화면에서 네이버 통계의 주제별 검색어 목록이 "맛집", "국내여행" 등으로 나뉘어 있는 것이 확인된다. 즉 네이버는 여행과 맛집을 서로 다른 주제로 구분한다. 블로그 전체 주제는 하나만 고르게 되어 있으므로 다음 중 하나를 선택해야 한다.

| 선택지 | 맞는 경우 |
|---|---|
| 국내여행 | 국내 지역 방문 글이 가장 많을 때 |
| 세계여행 (해외여행) | 해외 방문 글이 가장 많을 때 |
| 맛집 | 여행보다 식당·카페 후기를 더 자주 쓸 때 |

- **선택 기준:** 앞으로 가장 많이, 가장 꾸준히 쓸 유형을 고른다. 맛집 후기는 여행보다 자주 쓸 수 있고, 여행 글은 한 편의 정보량이 크다.
- 주제 목록의 정확한 이름과 글마다 주제를 따로 지정할 수 있는지는 실제 관리 화면에서 확인한 뒤 확정한다.
- 이 결정은 사용자의 실제 방문 패턴에 달려 있으므로 `BLOG_STRATEGY.md` 6절의 미결정 사항과 함께 정한다.

## 3. 카테고리 구조 (제안)

### 3.1 원칙

1. **지역이 기준이다.** 방문자가 "이 지역 글 더 보기"를 쉽게 할 수 있어야 한다.
2. **빈 카테고리를 만들지 않는다.** 글이 없는 메뉴는 블로그가 비어 보이게 한다. 글이 생길 때 카테고리를 만든다.
3. **처음에는 넓게, 쌓이면 나눈다.** 한 카테고리의 글이 많아지면 그때 하위 지역으로 쪼갠다.
4. **깊이는 2단계까지.** 상위 카테고리와 하위 카테고리만 쓴다.

### 3.2 시작 구조

```
국내여행
  └ (방문한 권역만 생성)  예) 서울·수도권 / 강원 / 제주 ...
해외여행
  └ (방문한 국가·도시만 생성)  예) 일본 / 베트남 ...
맛집·카페
  └ (방문한 권역만 생성, 국내여행의 권역 이름과 동일하게)
여행 정보
  └ 준비·교통·숙소 등 정보성 글
블로그 소개
```

- 맛집 카테고리의 지역 이름을 여행 카테고리와 똑같이 맞춘다. 같은 지역의 여행 글과 맛집 글을 서로 찾기 쉽게 하기 위해서다.
- 해외 맛집은 글 수가 적은 동안 해당 국가의 해외여행 카테고리에 함께 두고, 쌓이면 분리한다.
- 지역 모음글(D 유형)은 해당 지역 카테고리에 두고 대표 글 후보로 삼는다.

### 3.3 대안: 지역 통합형

여행과 맛집을 나누지 않고 지역만으로 카테고리를 만드는 방식도 가능하다.

```
서울·수도권 / 강원 / 제주 / 일본 / 베트남 / 여행 정보
```

| | 유형 분리형 (3.2) | 지역 통합형 (3.3) |
|---|---|---|
| 장점 | 맛집만 찾는 방문자에게 편하다 | 지역 연결이 가장 직관적이다 |
| 단점 | 같은 지역 글이 두 곳에 흩어진다 | 맛집 글만 모아 보기 어렵다 |
| 보완 | 글 끝의 내부 링크와 지역 모음글 | 글 제목 앞에 유형 표시, 태그 |

**권장:** 3.2 유형 분리형으로 시작한다. 지역 연결은 카테고리가 아니라 글 안의 내부 링크와 지역 모음글이 맡는다. 방문 지역이 소수로 집중된다면 3.3이 더 맞을 수 있으므로 시작 지역이 정해진 뒤 확정한다.

## 4. 내부 관리용 분류 (독자에게 보이지 않음)

카테고리와 별개로, 프로젝트 안의 글 데이터에는 아래 값을 붙여 관리한다. 자동화 도구가 연결 글을 찾고 통계를 묶는 데 쓴다.

| 필드 | 값 예시 | 용도 |
|---|---|---|
| 유형 | 여행후기 / 맛집후기 / 정보성 / 지역모음 | 작성 기준과 검수 항목 선택 |
| 지역 | 국가 > 권역 > 시·구 > 동네 | 연결 글 추천, 지역 모음글 구성 |
| 방문 기록 ID | 방문 한 건을 가리키는 식별자 | 글의 근거가 되는 방문 확인 |
| 방문일 | 2026-00-00 | 최신성 점검 |
| 대가 여부 | 내돈내산 / 협찬 / 원고료 / 제휴 링크 | 표시 문구 점검 (F1) |
| 목표 키워드 | 메인 1개 + 보조 | SEO 점검, 중복 방지 |
| 상태 | 글감 / 기획 / 초안 / 검수 / 발행 / 수정 필요 | 진행 관리 |

## 5. 태그 기준

- 글마다 3~5개, 본문에 실제로 나오는 검색 키워드와 연관된 것만 쓴다 (R4).
- 구성: 지역명 1~2개 + 대상(상호 또는 장소명) 1개 + 유형·상황 1~2개.
- 본문과 무관한 인기 태그, 광고를 유도하기 위한 태그는 쓰지 않는다. A1은 내용과 무관하게 광고를 유도하는 태그 삽입을 이용 제한 사유로 든다.

## 6. 아직 결정되지 않은 사항

- 블로그 주제 선택 (2절)
- 유형 분리형과 지역 통합형 중 확정 (3절)
- 국내 권역을 나누는 단위 (광역 시·도 단위로 시작할지, 더 넓게 묶을지)
- 여행·맛집 외 글(일상 등)을 아예 쓰지 않을지 여부. 주제 일관성(N1, N5) 관점에서는 쓰지 않는 쪽을 권한다.
