# AUTOMATION_ARCHITECTURE — Claude Code 기반 자동화 설계

- 문서 상태: 설계 초안 (승인 대기). 이 문서는 구조 설명이며, 아직 아무것도 구현하지 않았다.
- 근거 기호는 `PROJECT_OVERVIEW.md` 6절 참고

## 1. 먼저 이해할 것: 무엇을 자동화하고 무엇을 하지 않는가

| 자동화한다 (AI가 보조) | 자동화하지 않는다 (사람이 한다) |
|---|---|
| 글감 후보 정리와 중복 확인 | 방문, 촬영, 메모 |
| 제목·목차 후보 제안 | 맛과 경험에 대한 평가 |
| 방문 메모를 초안 문장으로 정리 | 가격·영업시간 등 사실 확인 |
| 검수표 점검, 빠진 항목 표시 | 최종 수정과 발행 결정 |
| 연결할 내 글 추천 | 네이버 편집기에서의 발행 |
| 통계 해석과 다음 글감 제안 | 수익화 신청, 협찬 수락 판단 |
| 오래된 글의 점검 목록 만들기 | |

이 구분의 근거는 N5다. 네이버는 AI를 "좋은 콘텐츠를 쓰기 위한 보조 도구"로 인정하면서, 최종 검토와 편집을 거쳐 창작자의 실제 경험을 담으라고 한다. 또한 AI가 기계적으로 생성·요약한 글의 무분별한 발행을 지양하라고 밝힌다.

## 2. 전체 흐름

```
 사람                     Claude Code                         사람
──────                  ─────────────                      ──────
방문·사진·메모 ─▶ ① 방문 기록 정리
                         │
통계·검색어 메모 ─▶ ② 글감 발굴 ───────────────────▶ [G1] 글감 승인
                         │
                  ③ 기획: 제목 후보·목차 ──────────▶ [G2] 제목·목차 승인
                         │
                  ④ 초안: 메모를 문장으로 ─────────▶ [G3] 읽고 직접 수정
                         │
                  ⑤ 점검: 검수표·SEO·표시 문구 ────▶ [G4] 사실 확인·최종 승인
                         │
                                                      ⑥ 네이버 편집기에 직접 발행
                                                         │
통계 붙여 넣기 ─▶ ⑦ 주간 회고 ◀──────────────────── 발행 기록 입력
                         │
                  ⑧ 오래된 글 점검 목록 ───────────▶ 수정 여부 결정
```

승인 지점(G1~G4)에서 사람이 "진행"이라고 하지 않으면 다음 단계로 넘어가지 않는다.

## 3. 단계별 설계

R1의 8개 역할을 여행·맛집과 이 프로젝트의 원칙에 맞게 바꿨다. R1의 Niche Strategist(주제 고르기)는 주제가 확정되어 있으므로 쓰지 않는다.

| 단계 | 역할 (R1 대응) | 입력 | 출력 | AI가 하지 않는 것 |
|---|---|---|---|---|
| ① 방문 기록 정리 | (신규) | 사용자의 메모, 사진 설명, 영수증 내용 | 방문 기록 카드 | 빈칸을 추측으로 채우지 않는다. 빈칸 목록을 사용자에게 되묻는다 |
| ② 글감 발굴 | Keyword Researcher | 방문 기록 목록, 사용자가 붙여 넣은 유입 검색어·자동완성 메모 | 글감 후보 표 (키워드, 검색 이유, 글 유형, 근거 방문 기록) | 방문 기록이 없는 장소를 후기 글감으로 내지 않는다. 검색량을 지어내지 않는다 |
| ③ 기획 | Title Writer + Outline Builder | 승인된 글감, 방문 기록 카드, 유형별 구성 | 제목 후보, 목차, 넣을 사진 위치, 연결할 내 글 | 카드에 없는 내용을 목차에 넣지 않는다 |
| ④ 초안 | Post Writer | 승인된 목차, 방문 기록 카드 | 초안과 "확인 필요" 표시 목록 | 경험·평가·가격·시간을 새로 만들지 않는다. 근거 없는 문장은 쓰지 않고 표시한다 |
| ⑤ 점검 | SEO Checker + Image Planner | 사용자가 수정한 글 | 검수표 결과, 고칠 문장 제안, 썸네일 문구 후보, 대가 표시 확인 | 통과 여부를 대신 결정하지 않는다 |
| ⑦ 주간 회고 | Growth Analyst | 사용자가 붙여 넣은 통계 | 잘된 글·안 된 글의 차이, 다음 글감 후보 | 붙여 넣지 않은 수치를 가정하지 않는다 |
| ⑧ 오래된 글 점검 | (신규) | 발행 기록의 방문일·확인일 | 재확인이 필요한 글 목록 | 정보를 임의로 고치지 않는다 |

## 4. 데이터 구조 (제안)

모든 데이터는 프로젝트 폴더 안의 텍스트 파일로 둔다. 데이터베이스나 외부 서비스는 쓰지 않는다. 초보자가 직접 열어 보고 고칠 수 있어야 하기 때문이다.

```
naver-travel-food-blog/
├── docs/                 설계 문서 (현재 단계)
├── references/           학습 자료 노트
├── visits/               방문 기록 카드 (방문 1건 = 파일 1개)
├── ideas/                글감 후보와 승인 상태
├── posts/                글 1편 = 폴더 1개 (기획, 초안, 최종본, 검수 결과)
├── regions/              지역별 글 목록 (연결 글 추천, 지역 모음글의 근거)
├── stats/                주간 통계 메모와 회고
└── templates/            방문 기록 카드, 유형별 구성, 검수표 양식
```

- 지역이 연결 기준이다. 방문 기록과 글은 모두 지역 값을 가지며, `regions/`에서 같은 지역의 글을 찾는다.
- 사진 원본은 용량과 개인정보 때문에 저장소에 넣지 않는다. 사진의 내용 설명만 방문 기록 카드에 적는다. (보관 위치는 미결정)
- `docs/` 외의 폴더는 2단계에서 승인 후 만든다.

## 5. Claude Code에서의 구현 방식 (제안)

초보자가 이해하기 쉬운 순서로 설명한다.

| 구성 요소 | 무엇인가 | 이 프로젝트에서의 쓰임 |
|---|---|---|
| 프로젝트 규칙 파일 | Claude Code가 작업할 때마다 읽는 지침 문서 | "방문하지 않은 곳을 쓴 것처럼 쓰지 않는다" 같은 절대 원칙을 항상 적용 |
| 스킬·명령 | 자주 하는 작업의 절차를 저장해 두고 이름으로 부르는 기능 | 방문 기록 정리, 글감 발굴, 기획, 초안, 점검, 주간 회고를 각각 하나씩 |
| 양식 파일 | 빈칸이 있는 틀 | 방문 기록 카드, 검수표 |
| 점검 스크립트 | 정해진 규칙을 기계적으로 확인하는 짧은 프로그램 | 필수 칸 누락, 태그 개수, 내부 링크 유무, 대가 표시 유무 |

- 판단이 필요한 일(문장 다듬기, 목차 구성)은 스킬로, 기계적으로 확인할 수 있는 일(칸이 비었는지, 개수가 맞는지)은 스크립트로 나눈다.
- 프로젝트 규칙 파일은 이 프로젝트 폴더 안에만 두어 저장소의 다른 작업에 영향을 주지 않게 한다.

## 6. 품질 통제 장치

| 장치 | 방식 |
|---|---|
| 근거 연결 | 초안의 경험·사실 문장은 방문 기록 카드의 항목에서만 나온다. 카드에 없으면 "확인 필요"로 표시한다 |
| 빈칸 유지 | 가격·영업시간 칸이 비어 있으면 글에서도 쓰지 않는다 |
| 승인 기록 | 각 글 폴더에 G1~G4의 승인 여부와 날짜를 남긴다 |
| 발행 전 검수표 | `CONTENT_GUIDELINES.md` 8절의 14개 항목. 사람만 판단할 수 있는 항목은 사람이 체크한다 |
| 대가 표시 점검 | 방문 기록 카드의 결제 항목이 협찬·원고료·제휴이면 표시 문구가 제목이나 첫 부분에 있는지 확인한다 (F1) |
| 중복 방지 | 같은 목표 키워드와 비슷한 제목의 기존 글이 있는지 확인한다 (N3의 유사문서 관점) |

## 7. 자동화 수준의 단계

한 번에 다 만들지 않는다. 각 수준은 앞 수준을 실제로 써 본 뒤에 올린다.

| 수준 | 내용 | 조건 |
|---|---|---|
| 0. 수동 | 양식과 검수표만 쓰고, 프롬프트를 직접 입력한다 | 첫 글들 |
| 1. 반자동 | 단계별 스킬·명령을 만든다 | 수준 0에서 같은 작업이 반복됨을 확인한 뒤 |
| 2. 연결 | 지역별 글 목록, 연결 글 추천, 점검 스크립트 | 글이 쌓인 뒤 |
| 3. 회고 자동화 | 주간 회고와 오래된 글 점검을 정기 실행 | 통계 입력이 습관이 된 뒤 |
| 4. 외부 연동 검토 | 통계 수집, 발행 보조 등 | 별도 검토와 승인 후 |

## 8. 범위 밖 (이 설계에 포함하지 않는 것)

- 네이버 로그인 자동화, 브라우저 자동 조작, 자동 발행·예약 발행
- 네이버 API 연결 (블로그 글쓰기 API의 현재 제공 여부도 확인하지 않았다)
- 댓글·공감·이웃 추가의 자동화. A1은 로봇 등으로 인위적인 클릭과 노출을 만드는 행위를 금지하며, 방문과 반응을 인위적으로 만드는 자동화는 이 프로젝트의 방향과 맞지 않는다
- 방문 없이 장소 정보를 수집해 글을 만드는 기능
- AI 이미지로 실제 사진을 대신하는 기능

수준 4의 외부 연동은 네이버의 약관과 정책을 먼저 확인하고, 사용자의 승인을 받은 뒤에만 검토한다.

## 9. 아직 결정되지 않은 사항

- 방문 메모를 어떤 방식으로 남길지 (휴대폰 메모, 음성 메모, 사진 캡션 등)와 Claude Code로 옮기는 방법
- 사진 원본의 보관 위치
- 이 프로젝트 파일을 어디에 보관할지 (현재 저장소의 작업 브랜치 / 별도 개인 저장소)
- 초안을 네이버 편집기로 옮기는 방식 (복사해 붙여 넣기 기준으로 가정)
