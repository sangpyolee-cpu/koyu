KOYU 플랫폼 브리핑을 자율 탐색형으로 작성한다. 사용자에게 되묻지 말고 끝까지 자동 실행하라. 단 DM 발송만은 예외이며 4번 항목을 따른다.
`CLAUDE.md` 의 절대 규칙을 전부 따른다. 특히 Google Drive / Google Docs 는 쓰지 않는다.
사용자에게 답할 때는 항상 공손한 습니다/입니다체를 쓴다. 해요체는 쓰지 않는다.

## 0. 준비 — 전주 비교 기준 확보

- `.\briefings\` 에서 가장 최근 브리핑 md 를 읽어 비교 기준으로 삼는다. 없으면 "첫 회차"로 진행한다.
    - 가장 최근 회차의 구조가 최신 양식의 기준이다. 이 파일의 양식과 다른 부분이 있으면 이 파일을 따른다.
- **주차 계산** — 오늘 날짜로 먼저 구한다.
    - 기준은 ISO 8601(월요일 시작)이다. 예: 2026-09-30 = 40주차(9/28~10/4).
    - 월 기준 주차는 월요일 시작 주로 세고, 그 달 1일이 속한 주를 1주차로 한다. 예: 2026-09-30 → 9월 5주차.
    - 브리핑 어디에도 "이번 호", "이번 주 브리핑" 같은 표현을 쓰지 않는다. 모두 "N주차"로 쓴다.
- **지난 제안사항 현황 파악**
    - 가장 최근 회차의 ⑤ 제안사항과 '지난 제안사항 현황' 표를 목록화한다.
    - 각 제안이 가리키던 대상이 지금 어떤 상태인지 확인한다(브라우저 관찰 또는 내부 시트). 상태는 중립 표현인 `유지` / `반영됨` / `확인 불가` 셋만 쓴다. 미이행 횟수는 세지 않는다.
    - 반영된 항목은 무엇이 어떻게 바뀌었는지 숫자로 쓴다.
    - 제안은 담당자가 필요할 때만 골라 쓰는 참고 의견이다. 실행 여부를 판정하거나 촉구하지 않는다.
- 지난 회차의 판단이 틀렸으면 명시적으로 철회하고 정정한다. 조용히 넘어가지 않는다.
    - 예: 전주에 특정 지표를 근거로 썼는데 그 지표가 신뢰할 수 없다고 확인되면 "해당 지표 폐기"라고 적는다.
- 최근 3개 회차 md 의 고정 지표 6개 값을 읽어 이번 주차 추이의 앞부분으로 쓴다. 고정 지표 표는 ② 플랫폼 인사이트 맨 위에 있다(구 양식 회차는 `KPI TRACKER`). 값이 없는 회차는 `—` 로 둔다.
- **로그인 상태 점검** — 탐색 전에 29CM · 무신사 · 오늘의집 · W컨셉 · EQL · 자사몰을 열어 로그인 여부를 확인한다.
    - 직접 로그인하지 않는다. 세션이 없는 플랫폼은 쿠폰 적용가를 `확인 불가` 로 두고, 해당 지표 값 뒤에 `(비로그인)` 을 붙인다.
    - 점검 결과는 Source 첫 줄에 플랫폼별로 적는다.
- **내부 매출 시트 읽기 (읽기 전용)** — Google Sheets 커넥터(`get_values`)로 읽는다. 브라우저로 시트를 열지 않는다.
    - `매출액자료(작업중)` (`10Jag9u2panDXo4b4-E3LgR8G_Sv9sXU65G99tM-wFy4`): '📊 매출보고' · '매출액자료' · '29cm' · '자사몰' · '무신사' 탭
    - `[원본] 판매 아카이브` (`1FsQdowP6s4PNgaYy2xjMzRZE8j6UMyAZetSU3GiOSxo`): '[2026] 월별 TOP SELLING' 탭
    - 읽은 값은 로컬 스크립트로 집계한다(주차별 · 상품군별 · 가격대별 · 반품률 등). 손으로 합산하지 않는다.
    - 시트에 쓰거나 새 파일을 만들지 않는다. 커넥터가 없거나 읽기에 실패하면 해당 항목은 `확인 불가` 로 둔다. 추정하지 않는다.
    - 매출 채널은 자사몰(최대), 29CM(2위), 무신사, 오늘의집, W컨셉 등이다. 시트에 없는 채널은 쓰지 않는다.

## 1. 탐색 — 플랫폼 6개, 각각 독립적으로

Chrome 은 플랫폼 공개 페이지를 직접 관찰할 때만 쓴다. 매출 데이터는 브라우저로 보지 않는다.

플랫폼별 순서: ① 카테고리 변화 발견 → ② 주요 상품·브랜드 발견 → ③ 가격·프로모션·랭킹 비교 → ④ KOYU와의 연관성 판단 → ⑤ 중요 변화만 채택

- 검색 결과 몇 개만 보고 판단하지 마라.
    - 카테고리 · 랭킹 · 베스트 · 신상품 · 기획전 · 검색결과 · 브랜드관 · 메인노출 · 가격/쿠폰 · 리뷰 증가 · 추천상품을 함께 본다.
    - 서로 다른 데이터에서 같은 변화가 반복 확인되는지 대조한다. 한 곳에서만 보인 변화는 `[단일 관찰]` 로 신뢰도를 낮춰 쓴다.
- 정렬을 바꿔가며 비교한다(추천순 / 판매순 / 신상품순). 같은 상품의 순위가 정렬별로 어떻게 다른지 본다.
- 가격은 반드시 쿠폰 적용 후 최종 판매가를 본다. 정가와 할인율만 보고 판단하지 않는다.
    - 카드 목록의 가격과 상품 상세 페이지의 가격이 다를 수 있다. 상세 페이지를 열어 확인한다.
- KOYU 주력 라인은 채널별 최종가를 전부 대조해 한 곳에 모은다.
    - 같은 제품에 서로 다른 가격이 걸려 있으면 그 주차의 최우선 관찰 대상이다.
- 시장 분포 지표를 잡는다: 상위 노출 상품의 가격 중간값 · 상한값 · 최저가 구간.
    - 전주 대비 어떻게 움직였는지, 중간값만 움직였는지 상한까지 깨졌는지 구분한다.
- 직접 확인하지 못한 항목은 전부 `확인 불가` 로 남긴다. 추정으로 메우지 않는다.
- 표본 수는 매주 같게 고정한다. 회차 간 비교는 같은 N 끼리만 한다.

| 플랫폼 · 정렬 | 고정 표본 |
|---|---|
| 29CM '차렵이불' 추천순 / 판매순 / 신상품순 | 각 상위 50 |
| 무신사 '차렵이불' 추천순 / 판매순(1주) | 48 / 24 (판매순은 참고용) |
| 오늘의집 '차렵이불' 기본정렬 | 상위 100 |
| W컨셉 '침구' 추천순 | 상위 60 |
| EQL 차렵이불 카테고리 신상품순 | 1페이지 |

- 페이지가 고정 N 보다 적게 나오면 실제 N 을 적고 비교에서 뺀다.

## 2. 경쟁 브랜드 선정 — 스스로 판단

고정 리스트를 쓰지 않는다. 아래 기준으로 오늘의 데이터에서 고른다.

- **상품 경쟁성** — 침구 · 차렵이불 · 베딩세트 · 패드 · 매트리스커버 · 베개 · 파자마 등 상품군 겹침
- **가격 경쟁성** — 유사 가격대 / 할인 후 실판매가 / 유사 세트 구성
- **고객·브랜드 경쟁성** — 동일 타깃, 유사 포지셔닝 · 디자인 무드 · 콘텐츠 스타일
- **플랫폼 경쟁성** — 동일 카테고리 상위 랭킹, 최근 급상승, 메인·기획전 노출 증가, 신규 입점 후 급성장
- **변화량(최우선 관찰)** — 할인율 증가, 가격 변경, 랭킹 급상승, 신규 상품 대량 등록, 리뷰·판매 급증, 메인 노출 획득, 대형 기획전 참여, 특정 컬러·소재 급부상

규칙:

- 핵심 3~5개만 쓴다. 특이사항 없는 브랜드는 제외한다.
- 지난주 목록을 그대로 반복하지 않는다.
    - 다만 지난주 관찰 대상으로 지정한 브랜드는 관찰 결과를 반드시 결론 낸다(계속 관찰 / 관찰 종료 / 위협으로 승격).
- 기존 항목에 없어도 시장 변화로 판단되면 조사해 포함한다.
    - 예: 특정 컬러가 여러 브랜드에서 동시 증가 / 특정 소재 반복 등장 / 특정 가격대가 상위 점령 / 저가 할인 경쟁 심화 / 신규 상품 대량 출시 / 플랫폼이 특정 스타일 집중 노출 / 리뷰 급증 상품.
- 우선순위: 1) 시장에서 새로 발생한 변화 → 2) KOYU에 직접 영향을 주는 변화 → 3) 경쟁 브랜드 움직임 → 4) 단순 참고.
    - 경쟁사 변화가 없어도 중요한 시장 변화가 있으면 반드시 보고한다.
- 경쟁 브랜드 움직임은 ② 플랫폼 인사이트 안에서 다룬다(별도 섹션을 두지 않는다).

## 3. 출력 구조 — 이 순서 그대로

### 3-1. 공통 작성 규칙

- **문체**: 본문 전체를 습니다/입니다체로 쓴다(~했습니다, ~입니다, ~보입니다). 딱딱하거나 AI가 쓴 것 같은 표현은 피하고, 실무자가 읽기 편한 업무 문체로 쓴다.
- **주차 표기**: "이번 호", "이번 주 브리핑", "전주 호" 같은 표현을 쓰지 않는다. 모두 "N주차"로 쓴다.
- **상품명**: 실제 상품명으로 쓴다. 내부에서만 통하는 약칭이나 카드 · ID 표현은 쓰지 않는다.
    - 예: `[29CM 단독] 플러피 컴포터 베딩 세트 아이보리`, `플러피 컴포터 베딩 세트 5col`
    - 쓰지 않는 예: "29CM 색상별카드", "5COL 카드"
- **금지 표현**: "미이행", "미실행", "조치 필요", "반드시 진행", "🔴 NOW", "NOW", "THIS WEEK", "MONITORING" 같은 업무 지시·긴급도 표현은 쓰지 않는다.
- **제안사항의 성격**: 실행 아이디어는 모두 "제안사항"이다. 담당자가 데이터를 보고 필요할 때만 골라 쓰는 참고 의견이며, 업무 체크리스트처럼 쓰지 않는다. 안 하면 큰일 나는 것처럼 쓰지 않는다.
- **항목 구조**: 인사이트 · 제안 항목은 사실 → 해석 → (제안) 순서로 쓴다.
- **출처 구분**: 브라우저 관찰은 `플랫폼`, 시트 기반은 `내부 시트` 로 따로 표시하고 섞지 않는다.
- **항목 수**: 항목을 무작정 늘리지 않는다. 의사결정에 도움이 되는 것만 쓴다.

### 3-2. 섹션 순서

제목: `# [KOYU PLATFORM BRIEFING] YYYY.MM.DD · N주차`

제목 바로 아래 인용문(`>`)에 아래 세 가지를 적는다.

- 주차 기준: ISO 8601(월요일 시작) N주차(M/D~M/D)
- 월 기준 주차: 예) 9월 5주차
- 매출 집계 기간: 예) 내부 시트 기준 9/1~9/29 누적

그다음 아래 순서로 쓴다.

- **## ① 핵심 요약**
    - 이 주차에 꼭 알아야 할 것 3줄. 번호 목록으로 쓴다.
    - 플랫폼 · 매출 · 상품 본문에 근거 수치가 있는 내용만 쓴다. 새 내용을 넣지 않는다.
- **## ② 플랫폼 인사이트**
    - **맨 위에 고정 지표 6개의 추이 표**를 둔다. 경쟁사가 아니라 측정 기준을 고정하는 것이다.
        - 표는 3열: `지표 | N주차 (M/D) | 추이 (과거 → 현재)`. 추이는 `57,900 → 64,900 → 59,900` 처럼 쓴다. 최근 4회까지.
        - 잴 수 없으면 `확인 불가`, 비로그인 값이면 `(비로그인)` 을 붙인다.
        1. 29CM 차렵이불 판매순 N50 가격 중간값 (쿠폰 적용 후 카드가)
        2. 무신사 차렵이불 추천순 N48 가격 중간값
        3. 오늘의집 차렵이불 기본정렬 N100 가격 중간값
        4. 플러피 컴포터 베딩세트 아이보리: 자사몰 최종가 − 전 채널 최저가 (0 이하면 자사몰이 최저가)
        5. 29CM 차렵이불 추천순 상위 50 안의 KOYU 상품 수
        6. 29CM 차렵이불 신상품순 상위 50 안의 상위 3개 브랜드 점유 칸 수
    - 표 아래에 집계 범위 변경 · 산식 설명 등 표 해석에 필요한 메모를 짧게 적는다.
    - 그 아래 **인사이트**를 번호로 쓴다. 가장 중요한 변화 3개 이내.
        - 제목 끝에 신뢰도를 붙인다.
            - `[복수 출처]` — 서로 다른 정렬 · 페이지 · 플랫폼 2곳 이상에서 같은 변화를 봤다.
            - `[단일 관찰]` — 한 곳에서만 봤다. 이 경우 제안은 확인 작업으로 제한한다.
        - 각 항목은 사실 → 해석 순서로 쓴다. 관련된 제안이 있으면 해석 끝에 `→ 제안 N` 으로 연결한다.
        - 우선순위는 매출 비중으로 정한다. 같은 크기의 변화라면 내부 시트 기준 매출이 큰 채널의 변화를 앞에 둔다.
        - 경쟁 브랜드 움직임은 2번 기준으로 고른 3~5개만 이 안에서 쓴다. 무엇이 변했는지 / KOYU에 어떤 영향인지를 쓴다.
    - 마지막에 **그 밖의 플랫폼 관찰** 항목을 둔다. 위에서 다루지 않은 변화만 사실 위주로 짧게 모은다(가격 / 할인 / 랭킹 / 기획전 / 컬러 / 소재 / 소비자 반응, 관찰 종료 브랜드).
- **## ③ 매출 인사이트** (출처: `내부 시트`)
    - 플랫폼 관찰과 매출을 결합해 의사결정에 도움이 되는 내용만 쓴다. 가능한 분석 예시: 채널별 주차 비교, 이상치(특정일 쏠림), 환불 · 반품, 랭킹 · 리뷰와 매출 대조.
    - 기본 구성:
        - 채널별 이번 달 목표 달성 표 (3열: 채널 | 실적 / 목표 | 달성률). 출처는 `내부 시트 '📊 매출보고'` 와 확인 시각.
        - 일할 진도 기준 달성률 한 줄.
        - 주차별 매출 표 (ISO 주차 기준). 진행 중인 주차는 집계 일수를 표기한다.
    - 시트 간 집계 기준이 다르면(예: 주문 탭 합계 vs 매출보고) 차이와 이유를 한 줄로 적는다.
    - 원인을 시트에서 알 수 없으면 추정하지 않고 `확인 불가` 로 쓴다.
- **## ④ 상품 인사이트** (출처: `내부 시트`)
    - 상품군 · 색상 · 가격대별 매출 집중도, 신상품 판매 추이, 반품률을 쓴다. 표본이 작으면(예: 주문 몇 건) 비교하지 않고 그 사실을 적는다.
    - 기본 구성: 상품군별 매출 표(매출 | 비중 | 비고), 판매가 구간별 표, 상품군별 특이사항.
    - 상품명은 실제 상품명으로 쓴다.
- **## ⑤ 제안사항**
    - 첫 줄 인용문: `> 아래는 검토용 선택지입니다. 진행 여부와 순서는 판단에 맡깁니다.`
    - 항목마다 **사실 → 해석 → 제안** 순서로 쓴다. 제안은 "~하는 방안이 있습니다", "A, B 중에서 고를 수 있습니다" 처럼 선택지로 쓴다. "~해야 합니다"는 쓰지 않는다.
    - 필요한 것만 쓴다. 근거가 약하면 제안하지 않는다. 제안할 것이 없으면 "이번 주차는 별도 제안사항이 없습니다"라고 한 줄만 쓴다.
- **## 데이터 범위**
    - 3열 표: `구분 | 현재 데이터로 가능 | 현재 데이터로 어려움`. 이번 주차에 확인 불가였던 분석과 그 이유(예: 노출 · 유입 · 전환 데이터 없음, 프로모션 기간 기록 없음)를 구분해 정리한다.
- **## 정정 · 철회**
    - 지난 회차 판단 중 틀린 것만. 없으면 "없음".
- **## Source**
    - 첫 줄: 플랫폼별 로그인 상태.
    - **플랫폼**: 확인 시각, 플랫폼별 확인 범위(고정 N 포함).
    - **내부 시트 (읽기 전용)**: 읽은 시트와 탭, 확인 시각.
    - **확인 불가** 항목 모음.
    - **비교 기준**: 비교한 이전 회차.
- **## 지난 제안사항 현황** (문서 맨 끝)
    - 지난 회차까지 나온 제안사항의 현재 상태. 담당 · 기한 판단은 사용자가 한다. 사실만 적는다.
    - 표는 4열: `제안 | 처음 제안 | 현재 상태 | 확인 내용`.
    - 상태는 `유지` / `반영됨` / `확인 불가` 만 쓴다. 미이행 횟수는 세지 않는다.
    - 반영된 항목은 다음 회차에 표에서 뺀다. 더는 유효하지 않은 제안은 '정정 · 철회' 에 이유를 쓰고 표에서 뺀다.

## 4. 배포

1. `.\briefings\YYYY-MM-DD.md` 로 저장한다. 이 파일이 단일 소스다.
2. 읽기용 `.\briefings\YYYY-MM-DD.html` 을 만든다.
    - 손으로 한글을 다시 타이핑하지 말고 md 파일을 읽어 변환하는 스크립트 `md2html.py` 로 만든다.
    - 파일 쓰기는 UTF-8(BOM 없음)로 한다.
3. **읽기용 페이지 게시**: claude.ai 아티팩트 `https://claude.ai/artifact/93A7MnJSGqq6kGVpjAG7qG` 를 같은 URL로 재게시한다.
    - 회사 공유가 켜져 있어 새 URL을 만들면 채널 멤버가 열 수 없다. 새 아티팩트를 만들지 않는다.
4. Slack MCP 또는 Slack 커넥터가 연결돼 있으면:
    - **캔버스 `F0BHH2YGWJV`**: 덮어쓰기만 한다. 새 캔버스를 만들지 않는다.
        - `slack_read_canvas` 로 먼저 읽어 `section_id_mapping` 을 확보한다.
        - 그 mapping 의 실제 section_id 로만 `replace` / `delete` 한다. ID를 지어내지 않는다.
        - 파라미터 형태: `canvas_id` + `sections: [{ edit_type, section_id, content }]` (`edit_type` 은 `replace|append|prepend|delete`)
        - 내용은 `md2canvas.py` 로 md 를 3KB 청크로 나눠 쓴다. payload 가 크면 `InputValidationError` 가 난다. 한 호출당 3KB 이하로 나누고, 각 응답이 돌려주는 새 mapping 을 다음 호출에 쓴다.
        - 인용문(blockquote) 섹션은 replace 할 때마다 ID가 바뀐다. 매번 재확인한다.
    - **채널 공지**: 브리핑을 업데이트할 때마다 `#i-유통`(`channel_id="C08RA54EEJX"`)에 읽기용 페이지 링크를 올린다. 형식은 아래 그대로 쓴다.
        - 첫 줄(굵게): `**[KOYU PLATFORM BRIEFING]**`
        - 본문: `M월 N주차 플랫폼 동향 브리핑입니다.` + 링크(3번의 아티팩트 URL)
        - 같은 주차에 이미 올렸으면 다시 올리지 않는다. 올리기 전에 채널의 최근 메시지를 읽어 확인한다.
    - **DM(`U08RATE5XHS`)은 기본적으로 보내지 않는다.** 9/30 업데이트 때 사용자가 "DM은 보내지 마"라고 결정했다.
        - 사용자가 이번 실행에서 명시적으로 DM 을 요청한 경우에만 보낸다. 이때도 발송 전에 보낼 전문(TODAY'S INSIGHT 대신 ① 핵심 요약 3줄 + 캔버스 링크 `https://koyuhaus.slack.com/docs/T08RK7ZLFL1/F0BHH2YGWJV`)을 보여주고 확인을 받은 뒤에 발송한다.
        - 확인 없이 발송하지 않는다. 이 단계에서는 되묻지 말라는 위 규칙의 예외다.
5. Slack 이 연결돼 있지 않으면 로컬 파일만 만들고, 마지막 보고에 "Slack 미연결" 이라고 쓴다.
6. **Google Drive / Google Docs 는 만들지 않는다. 영구 금지.**

## 5. 검증 — 건너뛰지 말 것

- 브리핑에 등장한 모든 플랫폼 숫자가 브라우저에서 직접 본 값인지 원본과 1:1 대조한다.
- 매출 · 상품 숫자는 시트 원본(또는 집계 스크립트 출력)과 1:1 대조한다. 합계 · 비중 · 달성률은 다시 계산해 일치하는지 본다.
- 고정 지표 6개가 모두 채워졌는지(값 또는 `확인 불가`), 추이의 과거 값이 이전 회차 md 와 같은지 대조한다.
- 같은 제품의 채널별 가격이 서로 모순되지 않는지 재확인한다.
- 문체 · 표현 스캔:
    - 금지 표현이 없는지 검색한다: `미이행`, `미실행`, `조치 필요`, `반드시 진행`, `NOW`, `이번 호`, `이번 주 브리핑`, `카드`(내부 약칭 용례).
    - 문장 끝이 습니다/입니다체로 통일돼 있는지 확인한다(~한다, ~이다, ~해요 종결이 있으면 고친다).
    - 상품명이 실제 상품명인지 확인한다.
- 캔버스를 다시 읽어 로컬 md 와 일치하는지 비교한다(불일치 0이 될 때까지).
- 오탈자 · 자모 깨짐을 스캔한다.
- 브라우저 탭을 모두 닫는다.
- 마지막에 3줄로 보고한다: 반영된 곳 / 확인 불가 항목 / 지난 주차 대비 정정 사항.
