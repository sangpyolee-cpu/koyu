KOYU 플랫폼 브리핑을 자율 탐색형으로 작성한다. 나에게 되묻지 말고 끝까지 자동 실행하라.
이 버전은 **클라우드·원격 세션 전용**이다. 이 PC 의 Chrome 로그인 세션, `C:\` 경로, 로컬 `CLAUDE.md` 는 없다.
아래 「절대 규칙」이 `CLAUDE.md` 를 대신한다.

## 절대 규칙 (예외 없음)

1. **직접 열어서 본 페이지의 데이터만 쓴다.** 추측 · 기억 · 웹검색(WebSearch) 결과 금지.
    - 직접 확인하지 못한 항목은 전부 `확인 불가` 로 표기한다.
    - 예외 하나: 내부 매출 시트 `매출액자료(작업중)` '📊 매출보고' 탭은 읽기 전용으로 쓴다. 출처를 `내부 시트` 로 따로 표시하고 관찰 데이터와 섞지 않는다.
2. **네이버쇼핑은 영구 제외.**
3. **로그인은 하지 않는다.** 클라우드에는 사용자의 로그인 세션이 없다. 직접 로그인하거나 자격증명을 입력하지 않는다.
4. **Google Drive / Google Docs 에는 아무것도 만들지 않는다.** 영구 금지. 시트 읽기만 허용한다.
5. **고정 경쟁사 리스트 금지.** 매번 플랫폼을 먼저 탐색하고, 오늘 의미 있는 변화가 있는 브랜드만 데이터 기반으로 고른다.
6. **지난주 브랜드 목록을 그대로 반복하지 않는다.** 과거 데이터는 비교 기준일 뿐이다.
7. **억지로 채우지 않는다.** 액션이 없으면 "없음"이라고 쓴다.
8. 항상 두 질문에 답한다: 오늘 KOYU 가 반드시 알아야 할 시장 변화는? 그래서 지금 무엇을 해야 하는가?

가독성: 가로로 긴 다단 표 금지. 상위 항목 → 4칸 들여쓴 하위 항목의 중첩 목록. 표는 숫자 비교 전용, 3열 이하. 한 줄에 여러 사실을 몰아넣지 않는다.

## 클라우드 환경 규칙

- **열람 수단**: 브라우저 MCP(Playwright 등)가 연결돼 있으면 그것을 쓰고, 없으면 WebFetch 로 위 URL 을 직접 연다. 웹검색으로 대체하지 않는다.
    - 목록이 JS 렌더링이라 상품 데이터가 안 나오면 그 플랫폼·정렬은 `확인 불가` 로 둔다. 다른 수단으로 메우지 않는다.
- **비로그인 공개가만 본다.** 쿠폰 적용 후 최종가는 `확인 불가`, 표기 가능한 가격에는 전부 `(비로그인)` 을 붙인다.
    - 아래 본문의 "쿠폰 적용 후 최종가" 지시는 로그인이 필요하므로 이 환경에서는 적용되지 않는다. 공개 판매가를 쓰고 그렇다고 적는다.
- **로컬 PC 브리핑과 값을 섞지 않는다.** 로컬 회차는 쿠폰 적용가 기준이라 공개가와 비교할 수 없다. KPI 추이는 `briefings/` 에 있는 클라우드 회차끼리만 잇는다. 로컬 회차 md 가 저장소에 들어 있으면 전주 판단 · 철회 확인에는 쓰되 숫자 추이에는 섞지 않는다.

## 0. 준비 — 전주 비교 기준 확보

- 작업 디렉터리의 `briefings/` 에서 가장 최근 브리핑 md 를 읽어 비교 기준으로 삼는다. 없으면 "첫 회차(클라우드)"로 진행한다.
- 지난 회차의 🔴 NOW / 🟡 THIS WEEK 항목을 전부 목록화하고, 이행 / 부분이행 / 미이행을 **공개 페이지 기준으로** 판정한다. 로그인이 필요해 못 보는 항목은 `확인 불가`.
    - 이행된 항목은 무엇이 어떻게 바뀌었는지 숫자로 쓴다. 미이행 항목은 이번 주에도 유효한지 재판단한다.
- 지난 회차의 판단이 틀렸으면 명시적으로 철회하고 정정한다.
- 최근 3개 회차 md 의 `KPI TRACKER` 값을 읽어 추이의 앞부분으로 쓴다. 값이 없는 회차는 `—` 로 둔다.
- 로그인 상태 점검은 하지 않는다. Source 첫 줄에 "클라우드 세션 — 전 플랫폼 비로그인" 이라고 쓴다.
- 내부 매출 확인 (읽기 전용) — Google Sheets 커넥터로 `매출액자료(작업중)` (`10Jag9u2panDXo4b4-E3LgR8G_Sv9sXU65G99tM-wFy4`) 의 '📊 매출보고' 탭을 읽는다.
    - 채널별 이번 달 목표 · 실적 · 달성률만 가져온다. 시트에 쓰거나 새 파일을 만들지 않는다.
    - 커넥터가 없거나 읽기에 실패하면 `확인 불가`. 추정하지 않는다.

## 1. 탐색 — 플랫폼 6개, 각각 독립적으로

플랫폼별 순서: ① 카테고리 변화 발견 → ② 주요 상품·브랜드 발견 → ③ 가격·프로모션·랭킹 비교 → ④ KOYU와의 연관성 판단 → ⑤ 중요 변화만 채택

- 검색 결과 몇 개만 보고 판단하지 마라.
    - 카테고리 · 랭킹 · 베스트 · 신상품 · 기획전 · 검색결과 · 브랜드관 · 메인노출 · 가격/쿠폰 · 리뷰 증가 · 추천상품을 함께 본다.
    - 서로 다른 데이터에서 같은 변화가 반복 확인되는지 대조한다. 한 곳에서만 보인 변화는 신뢰도를 낮춰 쓴다.
- 정렬을 바꿔가며 비교한다(추천순 / 판매순 / 신상품순). 같은 상품의 순위가 정렬별로 어떻게 다른지 본다.
- 가격은 반드시 쿠폰 적용 후 최종 판매가를 본다. 정가와 할인율만 보고 판단하지 않는다.
    - 카드 목록의 가격과 상품 상세 페이지의 가격이 다를 수 있다. 상세 페이지를 열어 확인한다.
- KOYU 주력 라인은 채널별 최종가를 전부 대조해 한 곳에 모은다.
    - 같은 제품에 서로 다른 가격이 걸려 있으면 그것이 그 주의 최우선 이슈다.
- 시장 분포 지표를 잡는다: 상위 노출 상품의 가격 중간값 · 상한값 · 최저가 구간.
    - 전주 대비 어떻게 움직였는지, 중간값만 움직였는지 상한까지 깨졌는지 구분한다.
- 직접 확인하지 못한 항목은 전부 `확인 불가` 로 남긴다. 추정으로 메우지 않는다.
- 표본 수는 매주 같게 고정한다. 회차 간 비교는 같은 N 끼리만 한다.

| 플랫폼 · 정렬 | 고정 표본 |
|---|---|
| 29CM '차렵이불' 추천순 / 판매순 / 신상품순 | 각 상위 50 |
| 무신사 '차렵이불' 추천순 / 판매순(1주) | 48 / 24 (판매순은 참고용) |
| 오늘의집 '차렵이불' 기본정렬 | 상위 100 |
| W컨셉 '침구' 추천순 | 상위 60 |
| EQL 차렵이불 카테고리 신상품순 | 1페이지 |

- 페이지가 고정 N 보다 적게 나오면 실제 N 을 적고 비교에서 뺀다.

## 2. 경쟁 브랜드 선정 — 스스로 판단

고정 리스트를 쓰지 않는다. 아래 기준으로 오늘의 데이터에서 고른다.

- **상품 경쟁성** — 침구 · 차렵이불 · 베딩세트 · 패드 · 매트리스커버 · 베개 · 파자마 등 상품군 겹침
- **가격 경쟁성** — 유사 가격대 / 할인 후 실판매가 / 유사 세트 구성
- **고객·브랜드 경쟁성** — 동일 타깃, 유사 포지셔닝 · 디자인 무드 · 콘텐츠 스타일
- **플랫폼 경쟁성** — 동일 카테고리 상위 랭킹, 최근 급상승, 메인·기획전 노출 증가, 신규 입점 후 급성장
- **변화량(최우선 관찰)** — 할인율 증가, 가격 변경, 랭킹 급상승, 신규 상품 대량 등록, 리뷰·판매 급증, 메인 노출 획득, 대형 기획전 참여, 특정 컬러·소재 급부상

규칙:

- 핵심 3~5개만 쓴다. 특이사항 없는 브랜드는 제외한다.
- 지난주 목록을 그대로 반복하지 않는다.
    - 다만 지난주 관찰 대상으로 지정한 브랜드는 관찰 결과를 반드시 결론 낸다(계속 관찰 / 관찰 종료 / 위협으로 승격).
- 기존 항목에 없어도 시장 변화로 판단되면 조사해 포함한다.
    - 예: 특정 컬러가 여러 브랜드에서 동시 증가 / 특정 소재 반복 등장 / 특정 가격대가 상위 점령 / 저가 할인 경쟁 심화 / 신규 상품 대량 출시 / 플랫폼이 특정 스타일 집중 노출 / 리뷰 급증 상품.
- 우선순위: 1) 시장에서 새로 발생한 변화 → 2) KOYU에 직접 영향을 주는 변화 → 3) 경쟁 브랜드 움직임 → 4) 단순 참고.
    - 경쟁사 변화가 없어도 중요한 시장 변화가 있으면 반드시 보고한다.

## 3. 출력 구조 — 이 순서 그대로

제목: `# [KOYU PLATFORM BRIEFING] YYYY.MM.DD`

- **## SUMMARY**
    - 이번 호에서 반드시 알아야 할 것 3줄. 번호 목록으로 쓴다.
    - 01 인사이트의 제목을 한 줄씩 압축한 것이다. 새 내용을 넣지 않는다.
- **## KPI TRACKER**
    - 아래 고정 지표 6개를 매 회차 같은 방법으로 잰다. 경쟁사가 아니라 측정 기준을 고정하는 것이다.
    - 표는 3열: `지표 | 이번 호 | 최근 4회 추이`. 추이는 과거 → 현재 순서로 `57,900 → 64,900 → 59,900` 처럼 쓴다.
    - 잴 수 없으면 `확인 불가`, 비로그인 값이면 `(비로그인)` 을 붙인다.
    1. 29CM 차렵이불 판매순 N50 가격 중간값 (쿠폰 적용 후 카드가)
    2. 무신사 차렵이불 추천순 N48 가격 중간값
    3. 오늘의집 차렵이불 기본정렬 N100 가격 중간값
    4. 플러피 컴포터 베딩세트 아이보리: 자사몰 최종가 − 전 채널 최저가 (0 이하가 정상)
    5. 29CM 차렵이불 추천순 상위 50 안의 KOYU 상품 수
    6. 29CM 차렵이불 신상품순 상위 50 안의 상위 3개 브랜드 점유 칸 수
- **## 01. TODAY'S INSIGHT**
    - 가장 중요한 변화 3개 이내. 각 항목은 «변화 → 의미 → KOYU ACTION» 3단으로 쓴다.
    - 항목 제목 끝에 신뢰도를 붙인다.
        - `[복수 출처]` — 서로 다른 정렬 · 페이지 · 플랫폼 2곳 이상에서 같은 변화를 봤다.
        - `[단일 관찰]` — 한 곳에서만 봤다. 이 경우 ACTION 은 확인 작업으로 제한한다.
    - 우선순위는 매출 비중으로 정한다. 같은 크기의 변화라면 '📊 매출보고' 기준 매출이 큰 채널의 변화를 앞에 둔다.
    - 각 ACTION 끝에 `→ 05-🔴` 처럼 액션플랜 연결 표시를 붙인다.
- **## 02. MARKET MOVEMENT**
    - 실제 변화가 확인된 항목만. 가격 / 할인 / 랭킹 / 상품 / 컬러 / 소재 / 플랫폼 큐레이션 / 소비자 반응.
    - 분포 지표는 전주 대비로 쓴다. KPI TRACKER 와 같은 숫자는 반복하지 않고 사분위 · 상한 등 추가 해석만 쓴다.
    - 01 에서 다루지 않은 시장 변화는 여기에 모은다 (예전 KEY MARKET CHANGES 의 역할).
- **## 03. COMPETITOR MOVEMENT**
    - 오늘 스스로 발견한 브랜드만 ① ② ③ … 번호로.
    - 브랜드별로 «무엇이 변했나 / 왜 중요한가 / KOYU에 어떤 영향» 을 쓴다.
- **## 04. KOYU STATUS**
    - 가격 · 할인 · 랭킹 · 리뷰 · 상품수 · 재고 · 노출 중 변화 있는 것만.
    - **매출 맥락 (내부 시트)** — 채널별 이번 달 목표 · 실적 · 달성률 표 (3열: 채널 | 실적 / 목표 | 달성률).
        - 출처를 `내부 시트 '📊 매출보고', 확인 시각` 으로 명시한다. 브라우저 관찰 데이터와 섞지 않는다.
- **## 05. KOYU ACTION PLAN**
    - 🔴 NOW — 오늘~내일 안에. 가능하면 1건으로 압축한다.
        - 왜 나머지는 NOW가 아닌지 인용문(`>`)으로 한 단락 설명한다.
    - 🟡 THIS WEEK — 이번 주 안에
    - ⚪ MONITORING — 보기만. 각 항목은 "무엇을 보면 결론이 나는가"를 적는다.
    - 액션이 없으면 억지로 쓰지 않는다. 비운 항목과 비운 이유를 마지막에 한 줄로 적는다.
    - 지난 호 항목의 이행 판정은 여기 쓰지 않고 맨 아래 ACTION TRACKER 로 보낸다.
- **## 정정 · 철회**
    - 지난 회차 판단 중 틀린 것만. 없으면 "없음".
- **## Source**
    - 첫 줄: 플랫폼별 로그인 상태.
    - 플랫폼별 확인 범위(고정 N 포함) + 확인 불가 항목 + 확인 시각.
- **## ACTION TRACKER** (문서 맨 끝)
    - 지난 회차까지 지정된 🔴 / 🟡 항목의 이행 현황. 담당 · 기한 판단은 사용자가 한다. 사실만 적는다.
    - 표는 3열: `항목 | 최초 지정 호 | 이번 호 판정` (판정 = 이행 / 부분이행 / 미이행 N회 연속 / 확인 불가).
    - 이행 완료된 항목은 완료 다음 회차에 표에서 뺀다.
